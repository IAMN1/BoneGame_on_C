# Экскурсия по коду

1344 строки C в одном файле, написанные в 2017 году человеком, который только что выяснил, что
существует `graphics.h`. Ниже — разбор того, как это на самом деле работает: обработка
прерываний, модель перерисовки, граф из `goto`, — и честный список того, что тут не так.

Ничего из этого не исправлено. Смысл репозитория в коде таким, каким он был.

## Вход в 640×480

```c
int gdriver = DETECT, gmode;
initgraph(&gdriver, &gmode, "c:\\turboc3\\bgi");
```

`DETECT` просит BGI выбрать лучший режим, который тянет видеокарта, а на любом VGA это 640×480
и 16 цветов. Третий аргумент — путь к драйверам, и он зашит намертво: именно из-за этой строки
игра не стартует, если Turbo C++ лежит не в `C:\TURBOC3`.
([Как чинить](RUN.ru.md#ошибка-bgi).)

Сразу под include'ами есть кусок вполне здравого смысла:

```c
int colorR = 4, colorG = 2, colorB = 1, colorC = 3, colorM = 5;
int colorLG = 10, colorLB = 9, colorW = 15;
```

Это индексы палитры EGA, которым дали имена. Дальше по файлу они свободно перемешиваются с
родными константами BGI — `WHITE`, `DARKGRAY`, `LIGHTBLUE`, — которые означают ровно те же
числа, так что один и тот же цвет записан двумя способами в зависимости от настроения.

## Как здесь вообще что-то рисуется

Ни буфера кадра, ни спрайтов, ни отслеживания «грязных» областей. Есть `cleardevice()` и
несколько десятков вызовов, которые кладут фигуры на экран. Вся графика игры — это пять
примитивов:

| Вызов | Для чего |
|---|---|
| `bar3d(x1,y1,x2,y2,depth,top)` | Все кнопки, глаза и блоки. `depth` даёт объёмную грань |
| `bar(x1,y1,x2,y2)` | Плоские заливки: рот, зубы, корпус C4 |
| `line` / `rectangle` / `circle` | Логотип загрузки, сетка клавиатуры, проводка на бомбе |
| `floodfill(x,y,border)` | Закрашивает грани, которые `bar3d` оставляет контуром |
| `outtextxy(x,y,s)` | Весь текст, по сетке 8×8 с масштабом от `settextstyle` |

Анимация везде сделана одинаково: нарисовать, `delay()`, нарисовать поверх. Смена улыбки на
оскал — это буквально красный `bar()` поверх зелёного, восемь белых прямоугольников на зубы и
шесть чёрных линий между ними ([765–850](../BoneMachine.c#L765-L850)).

Экран загрузки — самое амбициозное движение в файле. Две координаты идут навстречу друг другу,
из них рисуются восемь линий в фиксированные точки внутри окружности, а когда любая из
координат добирается до противоположного края, обе возвращаются на исходные:

```c
xl1 += 10; xl2 -= 10;
/* ...восемь вызовов line() с xl1 и xl2... */
if (xl1 >= 405 || xl2 <= 230) { xl1 = 230; xl2 = 405; }
```

Получается звезда, которая раскрывается, схлопывается в одну вертикальную линию и раскрывается
снова.

## Мышь — это прерывание

Ни цикла событий, ни колбэков. Есть прерывание DOS `0x33`, вызываемое руками:

```c
int Mouse_Regs(void) {
   regs.x.ax = 1; int86(0x33, &regs, &regs);   /* показать курсор        */
   regs.x.ax = 3; int86(0x33, &regs, &regs);   /* прочитать позицию+кнопки */
   delay(30);
   regs.x.ax = 2; int86(0x33, &regs, &regs);   /* спрятать курсор        */
}
```

Функция 3 оставляет x курсора в `regs.x.cx`, y — в `regs.x.dx`, состояние кнопок — в
`regs.x.bx`. `Button_Click` и `Button_Aiming` потом читают эти глобальные регистры, больше не
трогая прерывание, — поэтому любой интерактивный цикл в игре начинается с вызова `Mouse_Regs()`,
чтобы их обновить.

Тот самый `delay(30)` задаёт частоту опроса примерно 33 раза в секунду, и он же объясняет
мерцание курсора: тот показывается и прячется на каждом опросе.

Две детали. `Mouse_Regs` объявлена как `int` и не возвращает вообще ничего — Turbo C++ собрал
это без единого возражения. И наведение вынесено в отдельную функцию от клика, отличаясь лишь
`&& regs.x.bx == 1`, — а это вполне разумный способ разделить задачу.

## Меню — это граф из goto

`main()` тянется с [48-й по 414-ю строку](../BoneMachine.c#L48-L414) и почти целиком состоит из
меню. Подсвеченных состояний три, и каждое — это отдельный блок вызовов отрисовки,
скопированный с точностью до пяти пикселей. Переходы между ними — по меткам:

```
   round: ───────────► подсвечен режим 1 ──► Game_Mode_1()
     ▲   ▲                    │ ▲
     │   └────────────────────┼─┘
     │                        ▼
  punkt2: ──────────► подсвечен режим 2 ──► Game_Mode_2()
     ▲   ▲                    │ ▲
     │   └────────────────────┼─┘
     │                        ▼
  punkt3: ──────────► подсвечен выход
                              │
                              ▼
  round2: ──► «Do you wish to exit the game?» ──► subpunkt1: ──► exit(0)
```

Семь меток в `main`, ещё четыре внутри игровых режимов, а стрелки приходят как `getch()`,
возвращающий `0`, а следом скан-код: `80` — вниз, `72` — вверх, `77` и `75` — вправо и влево,
`13` — Enter. Каждый `case` перерисовывает меню целиком.

Индекс выбора и цикл перерисовки свернули бы всё это строк в сорок. Та версия, что существует,
работает, протестирована аудиторией в один школьный кабинет и совершенно не поддаётся правкам.

## Один раунд от начала до конца

Оба режима идут по одним и тем же восьми шагам ([`Game_Mode_1`](../BoneMachine.c#L765)):

1. Спросить баланс через `scanf` и крутиться, пока он `<= 0`.
2. Спросить число и крутиться, пока оно вне 1–6. Это вся валидация ввода целиком.
3. `Countdown_C4()` — подорвать бомбу.
4. `Head_Machine_On()` — нарисовать лицо.
5. Бросить три раза через `random(6)+1` и вывести каждый результат через `switch` из шести
   веток — по ветке на грань, и в каждой свой строковый литерал для `outtextxy`.
6. Сравнить и залить рот зелёным или красным.
7. Поправить баланс: `+150` или `-30`.
8. Ждать `RETRY` или `EXIT` — и либо `goto again_mod_1`, либо провалиться на экран статистики.

Пятый шаг — самый запоминающийся. Три броска рисуются не на костях, а в точках `(205,135)`,
`(445,135)` и `(325,220)` — то есть в левом зрачке, правом зрачке и на носу. Лицо автомата *и
есть* табло с барабанами, и нигде в коде об этом не сказано.

## Баги, о которых стоит знать

**Циклы ожидания в принципе не могут завершиться сами.**

```c
while (!Button_Click(180,420,300,440) || !Button_Click(360,420,480,440)) {
```

Курсор не может находиться в двух кнопках одновременно, поэтому хотя бы один вызов вернёт `0`,
его отрицание даст `1`, и условие всегда истинно. Каждый такой цикл покидается только явным
`break` или `goto` в теле. Правильным был бы `&&`; код работает, но по неправильной причине.

**Два игровых режима — это одна функция, набранная дважды.**
[765–1006](../BoneMachine.c#L765-L1006) и [1007–1254](../BoneMachine.c#L1007-L1254) отличаются
вторым `scanf`, тремя лишними слагаемыми в одном `if` и именами трёх счётчиков. Примерно треть
программы — дубликат.

**`randomize()` вызывается дважды.** Один раз в `main` и ещё раз при каждом вызове
`Graphics_Fon` — то есть генератор пересевается от системных часов при каждой перерисовке меню.

**Выплаты никто не сверил с вероятностями.** Первый режим выигрывает 1 − (5/6)³ = 42,1% раундов
при `+150` против `−30`, то есть ожидание `+45,8` за раунд *в пользу игрока*. Второй режим при
двух разных числах выигрывает в 70,4% случаев: `+96,7` за раунд. Автомат невозможно обыграть,
потому что он и не пытался.

## Что здесь сделано хорошо

Перечислять ошибки легко. Это заметить труднее — и именно поэтому игра остаётся играбельной
девять лет спустя:

- **Кнопка вынесена в функцию.** `Button()` и `Shadow_Button()` появились раньше, чем возникла
  хоть какая-то необходимость их выносить. Этот инстинкт и есть вся профессия.
- **Подсветка под курсором.** Каждая кнопка загорается под указателем — в программе, автору
  которой неоткуда было подсмотреть саму идею.
- **Два способа управления, и оба полные.** И с клавиатуры, и мышью можно дойти до любого
  экрана. У большинства первых проектов работает только один.
- **196 строк с комментариями** — в файле, который никто не собирался проверять.
- **Она доделана.** Есть заставка, меню, два режима, диалог подтверждения, экран статистики по
  итогам и честный `closegraph()` в конце. Это не демка. Это программа.
